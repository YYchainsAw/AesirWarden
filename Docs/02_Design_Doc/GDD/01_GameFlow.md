# 第一关完整游戏流程

> 目标设计；实现依据为 2026-09-30/10-07 记录：菜单、开场和探索交接已有 C++，完整流程与打包仍待验收。

课程基线为 [COURSE-20261018-R1](../../09_Course_Analysis/README.md)，原有需求沿用。终局竞争与恢复失败规则由本人于 2026-10-18 确认，记录为 `DEC-01`；它们是需求目标，实现和运行结果仍需分别核查。

## 流程定位

主菜单、关卡前段和 Boss 场地位于**同一第一关**。主菜单是一种关卡展示状态，不单独加载菜单地图。现有 L_OpenWorld 可以作为开发基础，正式关卡名称和场地布局待制作时确定。玩家完成关卡前段后抵达 Boss 场地，击败 Boss 即通关；失败后重试从第一关开头重新游玩，不设置 Boss 入口复活点。

完整路径：

启动第一关 → 营火主菜单 → 点击开始游戏 → 开场运镜与主角起身 → 关卡前段 → Boss 场地入口 → Boss 入场动画 → Boss 战 → Boss 败北与结束动画 → 通关结果

任意可战斗阶段玩家死亡 → 失败结果 → 重试 → 第一关开头；结果页另可返回营火主菜单或退出游戏。

先按 M1 完成 BT Boss 的全流程，再由 M2 接入冻结 PPO，M3 使用同条件战斗作对照。关卡前段提供移动、攻击、防御和闪避的熟悉过程；普通敌人遭遇按进度决定。当前顺序见[开发路线](../../05_Development_Guide/06_DevelopmentRoadmap.md)，总体边界见[范围表](../../01_Project_Overview/02_GoalsAndScope.md)。

## 核心循环

`进入遭遇 → 观察 Boss → 攻击／防御／闪避 → 胜负结算 → 查看结果 → 再次挑战或退出`。玩家的核心决策是读取攻击预兆并选择应对方式；Boss 的 BT/PPO 决策共用一个合法执行入口。

成长循环随 M4 细化，经验、资源、符文与装备的已有想法集中在[技能与成长设计](05_MagicSystem.md)。

## 场景节奏

| 区域 | 玩家体验 | 设计作用 |
| --- | --- | --- |
| 营火起点 | 主角坐在画面左侧的火堆旁；右侧显示“开始游戏”等菜单 UI | 同一场景中建立角色、气氛与第一关的起点 |
| 关卡前段 | 玩家从营火处出发，沿明确路线学习并使用基础战斗操作 | 为 Boss 战建立操作准备和空间推进感；不以堆积内容拉长流程 |
| Boss 场地入口 | 玩家抵达关卡末端后触发一次 Boss 登场 | 把探索节奏转换为遭遇节奏，明确 Boss 战开始边界 |
| Boss 场地 | 玩家读取攻击预兆并在攻击、守防、完美防御和闪避间选择 | 完成一场可记录、可比较的 Boss 遭遇 |

## 状态、镜头和控制权

<a id="br-game-01"></a>
**BR-GAME-01：阶段权限与交接。** 下表定义相机、输入、HUD 和 Boss 决策的合法阶段；自然完成与跳过使用同一交接入口，重复触发不得创建第二次入场或遭遇。依据为 GAME-FR01/02、G-UC-01/02/03。

| 阶段 | 画面与交互 | 进入下一阶段 |
| --- | --- | --- |
| 营火主菜单 | 摄像机以固定构图呈现左侧主角和火堆，右侧菜单获得键鼠/手柄焦点；主角坐姿与环境效果循环。玩家不能移动或发动能力，Boss 尚未进入战斗状态。首版菜单提供“开始游戏”“设置”（功能就绪后）和“退出游戏”；不显示尚未实现的“继续游戏”。 | 点击“开始游戏”后立即禁止重复点击，隐藏菜单，播放开场运镜。 |
| 开场运镜 | 镜头从营火构图移动到玩家视角；主角起身并准备出发。运镜结束时让游戏相机接管，显示必要 HUD，恢复移动与战斗输入。可跳过时，跳过与自然结束必须落在同一个玩家位置、朝向和控制状态。 | 相机与主角状态交接完成后进入关卡前段。 |
| 关卡前段 | 玩家自营火起点游玩到关卡末端。可使用简短场景提示介绍已有操作；暂不要求普通敌人、成长、符文或持久存档系统。 | 首次越过 Boss 场地入口触发区后进入 Boss 入场阶段。 |
| Boss 入场 | 暂停玩家战斗输入并切换到 Boss 登场镜头，展示 Boss、场地与威胁。此时 Boss 不做策略决策，也不能提前造成伤害。可跳过时，同样走统一交接入口。 | 动画结束或跳过后，镜头回到玩家，开放输入，显示 Boss 血条，关闭/标记场地入口并建立业务遭遇和初始决策记录。 |
| Boss 战 | Boss 由 BT 或冻结 PPO 选择高层动作，两者使用相同 Action/GAS 执行接口、场地规则和胜负条件。关卡过场时间不计入战斗 Episode。 | 当前角色产生终局事实后，按 BR-GAME-02 进入胜利或失败。 |
| 胜利收尾 | 一次性停止 Boss 决策和战斗输入，记录终局；播放 Boss 败北与关卡结束动画，再显示通关结果页。 | 玩家选择重试、返回主菜单或退出。 |
| 失败结算 | 播放玩家死亡反应，停止 Boss 决策并记录终局，再显示失败结果页。 | 玩家选择重试、返回主菜单或退出。 |

<a id="br-game-02"></a>
**BR-GAME-02：唯一终局。** 玩家死亡判负，指定目标 Boss 死亡判胜；双方同帧死亡按失败处理，普通敌人死亡不得提前通关。同次游玩最多产生一个终局结果，随后拒绝战斗输入、后续决策和旧局伤害/回调。依据为 GAME-FR05、G-UC-05，竞争规则见 `DEC-01`；当前实现差距见 [KI-02](../../06_Test_Doc/02_KnownIssues.md)。

## 重试与返回主菜单

<a id="br-game-03"></a>
**BR-GAME-03：重试入口与全局恢复。** 下列体验规则沿用 GAME-FR06/07、G-UC-06/07。G-UC-06 的触发、逐步异常、成功/失败保证及对象职责只在[重试用例与对象分析](../../09_Course_Analysis/01_RetryObjectAnalysis.md#g-uc-06)维护。

- **重试从关卡开头开始**：重新初始化第一关，玩家回到营火起点的初始可玩位置；关卡事件、敌人、血量、冷却、UI、相机、委托、策略请求与遥测的单局运行状态全部重置，旧局记录可保留归档。玩家必须重新走到 Boss 场地，不直接传送到 Boss 入口。
- 重试按钮默认**跳过营火菜单与开场运镜**，重载后短暂淡入并直接交还玩家控制；这是减少重复等待的体验设定。再次抵达 Boss 入口时仍播放 Boss 入场动画，可提供跳过。
- “返回主菜单”重新进入同一第一关的营火菜单状态：主角恢复坐姿，营火镜头和右侧菜单重新出现；不保留上一局的战斗状态。
- 当前设计不提供 Boss 入口检查点或“继续游戏”。若以后加入持久存档，应另行决定是否改变重试规则，不能把检查点加载与本版重试混为一谈。技术数据边界见[存档与重试设计](../TDD/04_SaveSystem.md)。

<a id="br-game-04"></a>
**BR-GAME-04：旧响应隔离。** 结束、重试或返回菜单后，属于旧游玩/遭遇/请求的伤害、策略或同伴响应不得修改当前状态。新一轮使用不同的游玩身份；取消请求是清理措施，接收端仍要复核身份与阶段。重试成功表示回到可操作起点，不提前建立新的 Boss 遭遇。

恢复失败时保持禁战斗，提供重新尝试或返回菜单；菜单也恢复失败时提供重新尝试或退出。恢复完成前不得把部分状态当作新一轮成功。该需求目标依据 `DEC-01`，步骤和失败保证见 G-UC-06 局部规格。

## UI 呈现与输入

- 营火画面以左侧主角与火堆为视觉中心，右侧显示“开始游戏”“退出游戏”，设置功能就绪后再加入。按钮支持键鼠和手柄，文字避开角色与火焰高亮；开始按钮点击后防重复输入，菜单淡出。
- HUD 展示已接通的生命、守防和操作提示；Boss 血条在入场交接后显示。不可防御攻击需要独立、可辨认的提示，技能冷却随对应能力接通。
- 结果页明确显示胜负及“重试”“返回主菜单”“退出游戏”；UI 获得输入焦点，避免战斗输入穿透或连续点击重复重启。各阶段相机、HUD、控制权按上表交接，过场跳过与自然结束走同一出口。
- BT/PPO 模式、模型 ID 与回退原因放在实验配置或遥测中，普通玩家界面显示战斗反馈。

现有 [WBP_CombatResult](../../../Content/Aesir/UI/Results/WBP_CombatResult.uasset)与 [WBP_CombatHUD](../../../Content/Aesir/UI/HealthBars/WBP_CombatHUD.uasset)可定位，具体按钮、焦点与显示时机仍需运行验收。

<a id="br-game-07"></a>
**BR-GAME-07：退出与输入隔离。** 沿用 GAME-FR08、G-UC-08：营火菜单和结算页均提供退出；退出停止后续请求并关闭目标运行程序，不等待服务响应。菜单/结算操作不得同时触发战斗动作。PIE 停止与 Windows 包进程退出分别检查，前者不能替代后者的证据。

## 高风险用例的局部规格

下列规格供课程模型和开发共用，行为依据为上述 BR；详细测试步骤见[开发检查清单](../../06_Test_Doc/01_VerificationMatrix.md)，其他用例继续沿用本轮课程 Word 的原规格。

<a id="g-uc-03"></a>
### G-UC-03 挑战 Boss

参与者为玩家；触发为首次有效进入 Boss 入口。前置是当前游玩未结束、指定 Boss 有效、尚未启动本次遭遇。

| 步骤 | 参与者动作与系统响应 |
| --- | --- |
| 1 | 玩家进入触发区，系统锁定本次入场，按 BR-GAME-01 禁用战斗输入、Boss 决策和伤害，开始入场表现。 |
| 2 | 玩家等待或跳过；系统使用同一完成入口恢复角色、相机、HUD 和控制状态。 |
| 3 | 系统确认双方可战斗后，将新遭遇关联当前游玩，按 RL 契约创建初始决策记录，转入 G-UC-04。 |

| 扩展 | 条件、响应与落点 |
| --- | --- |
| 1a / 2a | 入口或完成事件重复到达：忽略重复事件，继续原阶段，不另建遭遇。 |
| 2b | 入场资源或恢复失败：保留禁止战斗的安全状态并报告失败，允许重新尝试或返回菜单；菜单也失败则允许重新尝试或退出，不执行步骤3。 |
| 3a | 策略服务失败：按 [BR-RL-03](../../08_RL_Research/01_BossRLContract.md)的回退规则处理；不得提前伤害或绕过动作合法性。连续达到阈值后使用 BT 至本遭遇结束，依据为 `DEC-02`。 |
| 3b | 旧游玩/请求的响应到达：按 BR-GAME-04 丢弃，继续当前合法阶段。 |

成功保证：当前游玩只关联一个已就绪的 Boss 遭遇，双方可以战斗。失败最小保证：未完成交接时不开放战斗权限，不将部分恢复报告为开战成功。Episode 与策略记录段的对应关系由 RL 契约维护，不能从一次业务遭遇推断只有一条遥测记录。

<a id="g-uc-05"></a>
### G-UC-05 查看结算

参与者为玩家；触发为当前游玩中的玩家或指定 Boss 产生有效死亡事实。前置是本次游玩尚未形成终局结果。

| 步骤 | 参与者动作与系统响应 |
| --- | --- |
| 1 | 系统校验死亡事实属于当前游玩与指定角色，归并同帧终局事实后按 BR-GAME-02 判定结局；双方同帧死亡判失败，不能由回调先后直接定胜负。 |
| 2 | 系统形成唯一结果，关闭战斗输入/决策，隔离后续伤害和异步消息；播放适用收尾表现并显示结算。 |
| 3 | 玩家选择重试、返回菜单或退出；系统仅接收该界面合法操作，分别转入 G-UC-06、G-UC-07 或 G-UC-08。 |

| 扩展 | 条件、响应与落点 |
| --- | --- |
| 1a / 2a | 重复死亡或结算回调：保留第一次合法结果，继续已有收尾/结算，不创建第二个结果。 |
| 1b | 普通敌人死亡或旧局事实：忽略其终局请求，当前游玩按原状态继续。 |
| 2b | 终局后投射物、命中事件、策略/同伴响应到达：按 BR-GAME-02/04 拒绝其战斗影响，保留结果；需用实测验证具体资产与回调。 |
| 3a | 重复点击或已有状态切换：忽略重复请求，继续第一次合法切换。 |

成功保证：结果已显示，本次游玩不再接受战斗行为。失败最小保证：不能因界面或服务错误再次结算、恢复旧战斗或让旧响应污染后续游玩；恢复失败保持禁战斗并给出重新尝试/返回菜单，菜单也失败时可重试/退出。本用例不宣称 GameMode 或结果 Widget 已通过验收。

## 流程实现约束

- 首段流程使用原生 `AAesirLevelFlowDirector`，负责菜单、开场和探索阶段的状态、输入及相机交接；蓝图配置场景引用、菜单按钮和表现。具体接入步骤见[第一关流程控制器接入](../../05_Development_Guide/05_LevelFlowGuide.md)。Boss、终局和重试状态目前只预留，尚未由此控制器接通。
- 菜单、运镜、游玩、Boss 入场、战斗与结算必须是可区分的状态。镜头负责表演；统一的流程控制负责输入、相机、HUD 和阶段切换；GameMode 负责一次性胜负判定。不要让 Sequence 的多个完成/跳过出口分别创建 Boss Episode。
- 业务遭遇只从入场交接完成、玩家和 Boss 都可行动时开始；其策略/Episode 记录遵循 [RL 契约](../../08_RL_Research/01_BossRLContract.md)。BT/PPO 选择属于实验配置，不放在普通玩家的主菜单上；实际回退效果仍须单独验收。
- 当前 GameMode 只登记关卡 BeginPlay 时已有的敌人。若关卡前段加入普通敌人或把 Boss 改为动态生成，必须重新核对“仅 Boss 死亡才通关”的胜利判定；不能仅依赖现有剩余敌人数推断 Boss 结局。
- 关卡可以先用占位场景和短镜头跑通“菜单 → 关卡前段 → Boss → 胜败 → 重试／返回”，再制作正式动画、音画和 UI。当前可定位 [GameMode 胜负事件](../../../Source/AesirWarden/Private/Framework/AesirCombatPrototypeGameMode.cpp)与 [结果 Widget](../../../Content/Aesir/UI/Results/WBP_CombatResult.uasset)；完整流程尚未在本工程验证。

## 验收要点

1. Windows 包冷启动直接显示第一关营火菜单；开始后不加载另一张菜单/游戏地图，运镜结束的玩家位置、朝向、输入与相机正确。
2. Boss 入场只触发一次；过场期间没有 Boss 决策、命中或 Episode 时长；自然结束和跳过都能正常开战。
3. Boss 死亡只触发一次收尾动画和通关页；玩家死亡只触发一次失败页。结果页按钮与输入焦点可用。
4. 连续失败并重试两次，均从关卡开头重新游玩，旧敌人/能力/UI/策略请求不残留；恢复起点时尚无新遭遇，到达 Boss 并完成入场后才建立新遭遇及其决策记录。
5. 返回主菜单后恢复营火构图、主角坐姿及右侧菜单；键鼠和手柄均能操作按钮，输入不会穿透 UI。
6. 菜单和结算页均可退出；服务正常、断连或超时时 Windows 包进程都能结束。恢复失败保持禁战斗且可重试/返回菜单；菜单也失败时可重试/退出。双方同帧死亡得到唯一失败结果。以上需求确认不等于测试通过。

M1 先用 BT 通过上述流程；M2 再验收 PPO 及服务故障回退路径。测试证据记录在[验证矩阵](../../06_Test_Doc/01_VerificationMatrix.md)。
