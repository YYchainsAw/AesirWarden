# 玩家技能与成长设计

> 目标基线：2026-10-07，完善玩家数值、技能和手感。具体符文、成长与存档方案为已有草案，实施前重新确认。

## 已确认的开发目标

M4 完善玩家属性、伤害、冷却、选定技能及攻击/翻滚手感，与 M2 的 Boss 战斗版本协调。开发顺序和任务见[开发路线](../../05_Development_Guide/06_DevelopmentRoadmap.md)，现有基础战斗规则见[战斗设计](03_CombatDesign.md)。

[COURSE-20261018-R1](../../09_Course_Analysis/README.md)沿用已有游戏/RL/NPC需求；下表的两槽、五属性等级和成长等细节没有自动成为课程必交。课程核心未引入尚未定义的法力/体力消耗，后续 M4 若改变资源规则，应形成新的明确决定并同步受影响模型与测试。

## 当前可定位的基础

[玩家 AttributeSet](../../../Source/AesirWarden/Public/Abilities/AesirPlayerAttributeSet.h)有 RunePower、CooldownHaste、PhysicalPower、DamageReduction、GuardPressure 等运行时字段；[Ability 资产目录](../../../Content/Aesir/Abilities)有 Boss 与 Guard 能力。2026-09-29 的静态记录尚未确认通用 Inventory/Loot、两槽符文装备、经验/技能点和持久存档闭环。

## 候选能力管线

若采用符文/装备授权方案，可沿以下管线接入；最终以选定技能为准。

1. 定义稳定的技能/符文 ID、GameplayTag、对应 GA 和 UI 数据；若有持久进度，加载后恢复能力选择。
2. 装备变化时由 ASC 授予或移除对应能力；基础 Guard 与该装备授权分开，避免更换装备误删基础防御。
3. 输入或战术指令请求施放；UE 校验装备、目标和状态，GAS 校验冷却、标签及选定的成本。
4. 能力驱动 Montage/Ability Task、投射物或命中检测、GE 与 Gameplay Cue；UE 结算伤害与受击。
5. UI 显示冷却和可理解的失败反馈；需要时记录激活、拒绝、命中与中断。

持久等级/装备定义与瞬时 Health、GuardPressure、冷却分别保存；若采用永久成长，通过选定曲线/GE 转换为运行时 GAS 数值。装备类别可使用定义资产或互斥标签表达。重试的技术处理见[重试与存档边界](../TDD/04_SaveSystem.md)，GAS 职责见[GAS 架构](../TDD/02_GasArchitecture.md)。

## 候选验收场景

下表只在采用对应方案后转为验收项，当前没有通过记录。先确定技能清单、ID、标签、冷却和期望数值，再调整测试步骤。

| ID | 采用方案后的操作 | 要检查的结果 |
| --- | --- | --- |
| M-01 | 装备选定的技能/符文；若采用两槽方案则装入两枚 | ASC 授予对应能力，基础 Guard 保留 |
| M-02 | 施放后立即重复输入 | 首次执行，冷却期由 GAS 拒绝并给出反馈 |
| M-03 | 装入无效/未拥有的 ID，或超出选定槽数 | 本地拒绝；装备和 ASC 能力保持一致 |
| M-04 | 在死亡、眩晕或技能要求的目标条件不成立时施放 | 无非法伤害或效果，拒绝原因可追查 |
| M-05 | 修改选定成长项并进入战斗 | 持久等级按最终公式转换，运行时属性与预期一致 |
| M-06 | 若采用存档，保存、退出后重载 | 拥有/装备与能力授权一致，不重复授予 |
