# BT–PPO 评估方案

> 正式采集前固定条件和统计方法；本文没有预填实验结果。BR-RL-05 / NFR-RL-01见[RL契约](01_BossRLContract.md)，DEC-02已确认一遭遇多策略段、回退单独归组。

## 比较层级

| 层级 | 对照与条件 | 可回答的问题 |
| --- | --- | --- |
| 模拟器独立测试 | 同一模拟器/玩家画像/种子，RuleBossPolicy对冻结PPO；选模900局不得复用 | 该模拟器条件下的策略效果 |
| UE同条件对照 | BT与冻结PPO使用相同Boss资产、共享执行器、数值、初态、玩家行为和结算规则 | 游戏内战况响应、行为差异与成本 |
| 体验检查 | 客观指标稳定后比较可读性、公平性、挑战与重复感 | 指定玩家样本中的体验，不从胜率直接推断 |

正式主对照默认不加入同伴变量。需比较AI队友时另设条件，不能将NPC协作差异混入Boss策略结论。冻结PPO部署期间不更新模型权重。

## 遭遇与策略段的归组

[RL契约](01_BossRLContract.md)区分一场BossEncounter与源码称为Episode的策略记录段。当前回退将RL段标Aborted并开始Fallback段，物理战斗继续；不能将这些记录段直接当作互相独立的多场战斗。

| 原始情况 | 必须保留的数据 | 报告与归组约束 |
| --- | --- | --- |
| 纯BT遭遇 | 遭遇ID、BT段、终局 | 标明BT条件 |
| PPO全程且无回退 | 遭遇ID、模型、PPO段与终局 | 可标“无回退PPO”；仍保留拒绝/合法无动作 |
| PPO故障后切BT | 原始分配条件、PPO段、切换原因/时刻、Fallback段与最终终局 | 单独归为PPO→BT回退遭遇，保留原始分配标签；不并入纯PPO或纯BT成绩。段内指标可拆分报告，主研究比较需声明是否另含按原始分配的补充分析 |
| Aborted段 | 原因、段内记录、所属遭遇及后继段 | 段中止不必然是遭遇失败；不得当作独立失败样本重复计局 |
| 玩家重试 | 旧游玩/遭遇终局、新游玩身份及入口 | 新一局单独采样，不能复用旧段或迟到响应 |
| 超时/崩溃/主动中止 | 原始条件、原因、已采数据和是否产生终局 | 按预定规则列入或排除并报告数量，不事后挑样本 |

采集清单必须关联 `playthrough_id → encounter_id → segment/episode_id → decision/request` 或等价可核对标识。已确认的归组规则写入实验manifest；具体样本量、统计方法和任何新增分析仍在采集前记录，不以已确认回退规则推断整个实验方案H0冻结。

## 指标定义

| 目标 | 至少记录什么 | 解释边界 |
| --- | --- | --- |
| 胜负与效率 | 遭遇级胜/负/超时/中止数、区间、时长、双方伤害 | 按画像与策略条件拆分，回退数量可见 |
| 战况响应性 | 预定义事件（距离/状态/动作可用性改变）时刻，后续首次合法决策及实际启动时刻，拒绝原因 | 先固定事件与响应判据；PPO根据观察变化不等于在线学习 |
| 行为多样性 | 九动作尝试/接受分布、相邻重复率、按距离/状态分层的分布 | 先固定“尝试”或“接受”的分母；动作越多不直接代表更公平或更好 |
| 可靠性 | 协议/非法动作/执行拒绝分别计数，合法无动作数，故障/回退率 | 合法state_locked不混进故障率，执行端拒绝不冒充HTTP故障 |
| 成本 | HTTP往返、服务推理、UE执行请求耗时；帧时间/平均及1% low与极端帧率 | 分开加载与战斗、正常与故障路径，记录机器/设置/样本量 |

NFR-RL-01要求耗时可测量和可区分。客户端现有 `PolicyEvaluationMilliseconds` 接入值可能是HTTP往返，应按真实字段语义报告，不能当作纯模型推理耗时。Python响应中的 `inference_milliseconds` 单独取值。

NFR-GAME-02的30FPS当前是目标；最低硬件与帧时间/低帧判据未冻结前，只报告实际结果。任何“改善”结论同时给样本、区间、效果大小与失败例；体验问卷另定招募、顺序和分析方式。
