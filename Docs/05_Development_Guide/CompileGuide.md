# 编译与故障定位

> 状态：工作流程草案 · 2026-09-29；未声明本轮已完成干净构建。

常规顺序：关闭可能占用生成文件的编辑器进程 → 用 UE 5.8 生成工程文件 → 编译 `AesirWardenEditor` → 启动编辑器并检查 Blueprint/资产加载 → 运行目标关卡 PIE。先记录**第一个**编译错误的文件与行号，再判断是 C++、UHT、模块依赖、插件版本还是 Blueprint 父类问题。

公共头或 `UCLASS/USTRUCT/UENUM/UPROPERTY` 改动后，优先执行完整编辑器构建和重启。只在确认生成缓存损坏、工程已备份且清楚目标路径时清理本地中间产物；不要把清理命令作为第一步。修改 `Build.cs` 或插件后应核对依赖并重新生成工程文件。

发布构建另按 [ReleaseChecklist](../07_Release/ReleaseChecklist.md)记录 Cook、打包、启动、服务故障与性能结果；“C++ 编译成功”不等于完整游戏流程可用。
