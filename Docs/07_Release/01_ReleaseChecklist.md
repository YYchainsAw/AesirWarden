- [ ] 记录代码、完整资产快照、构建和依赖；PPO版本另记模型/哈希、契约、服务版本及启动方式，错误材料不能作正式部署。
- [ ] 统一NPC服务端口与UE配置，记录旧/新协议实际使用路径及当前游戏/角色/能力目录；外部LLM按BR-NPC-06说明数据外发和保留范围。
- [ ] 核对素材许可、署名和课程/试玩说明；检查测试能力、调试UI、本机路径和秘密配置。

## 打包后

- [ ] 冷启动走开始→探索→Boss胜败→结算；测指定Boss胜利、玩家失败及双方同帧死亡按失败，只结算一次（FLOW-01、MATCH-01/01a/b）。
- [ ] 连续重试至少两轮、返回菜单再开始；覆盖恢复中重复点击、旧回包、恢复失败和成功恢复未进Boss不建遭遇（C-08a..d）。
- [ ] 菜单和结算页可退出；恢复失败禁战斗并可重试/返回，菜单恢复也失败时保留重试与退出；离线/超时不阻塞出口（EXIT-01..03）。
- [ ] PPO包分别验证正常/无动作/断连/超时/坏协议/非法动作；三连错切BT到本场终局、完整合法响应清零，不执行旧响应（RL-FAULT-01a..g）。
- [ ] 核对同一遭遇的PPO与Fallback记录段关联及归组，不能把回退胜利标为纯PPO（RL-EPISODE-01、BR-RL-05）。
- [ ] 启用NPC的包执行相应文本/语音/自主/事件重复/隔离/记忆清理与实际阶段回执检查；现有accepted/executed协议和目标反馈差距如实列出（NPC-*）。
- [ ] 测机器/画质/平均及1% low/极端帧率与帧时间；PPO另测HTTP/推理/执行耗时，加载和战斗分开。30FPS是项目目标，未冻结正式硬件判据前只报告实际值。
- [ ] 处理阻断游玩的[已知问题](../06_Test_Doc/02_KnownIssues.md)，保留剩余限制；具体步骤与实际结果写入[开发检查清单](../06_Test_Doc/01_VerificationMatrix.md)。
